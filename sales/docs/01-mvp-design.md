# 営業管理ツール MVP設計書（確認用ドラフト）

対象：顧客管理＋案件管理＋活動記録（MVP）。ダッシュボード・リマインド・契約/制作連動は後続。
状態：**確認事項は回答済み（2026-11-10）**。設計全体の了承後に実装へ入る。

---

## 1. 技術スタック（提案）

| 項目 | 採用案 | 理由（1行） |
|---|---|---|
| 画面 | Next.js 14（App Router）＋TypeScript | 同リポジトリの既存LPと同じ構成で、保守を揃えられる |
| 認証・DB | Supabase（Auth＋PostgreSQL） | ログインと「役割ごとの見える範囲」をDB側（RLS）で強制でき、画面のバグで情報が漏れにくい |
| 見た目 | Tailwind CSS（スマホ優先のレスポンシブ） | 外出先のスマホ利用が前提のため |
| 公開 | Vercel | Next.jsをそのまま公開でき、無料枠から始められる |

**代替案**
- kintone / AppSheet などのノーコード：最短で動くが、確度×金額の集計や制作キャパ警告など独自ロジックに限界。ユーザー課金が人数分かかる。
- Next.js＋Prisma＋自前のDB/認証：自由度は最大だが、認証や権限まわりを自作する分だけ時間と運用負担が増える。

**置き場所**：このリポジトリの `sales/` に独立したアプリとして作る（既存LPとはビルドも設定も分ける）。

**必要なもの**：Supabaseのプロジェクト（無料プランで可）。作成後に「URL」と「anonキー」を環境変数に設定する。

## 2. データモデル

金額はすべて**税別・円・整数**で保存する。日時はUTC保存、表示は日本時間。

### users（利用者＝Supabase認証と1対1）
| 列 | 内容 |
|---|---|
| id | 認証ユーザーID |
| name | 表示名 |
| role | `manager`（部長）／`admin`（運用管理者：充）／`sales`（営業）／`production`（制作） |
| is_active | 退職者は無効化（データは残す） |

### customers（顧客＝店舗）
| 列 | 内容 |
|---|---|
| store_name | 店舗名（必須） |
| industry_id | 業種（マスタ：車両販売店／カスタムショップ／パーツメーカー…） |
| area_id | エリア（マスタ） |
| contact_name / phone / email | 店舗担当者・電話・メール |
| portal_listed | ポータル掲載の有無（はい/いいえ） |
| portal_note | 掲載ポータル名など（任意） |
| instagram_url / instagram_last_posted_on | Instagram URL・最終更新日 |
| has_existing_deal | 既存取引の有無 |
| priority | A／B／C |
| owner_id | 営業担当（users） |
| memo | メモ |
| dedupe_key_name / dedupe_key_phone | 重複チェック用（店舗名と電話番号を正規化した値。自動計算） |
| created_at / updated_at / deleted_at | 削除は「論理削除」（誤削除の復元のため） |

**重複チェック**：登録・CSV取り込み時に、次のいずれかが一致したら「重複の可能性」として確認を出す。
- 正規化した店舗名（全角半角・空白・「株式会社」等を除去）
- 正規化した電話番号（ハイフン・空白除去）
- Instagram URL

### deals（案件）
1顧客に複数案件を持てる（例：失注後の再提案）。
| 列 | 内容 |
|---|---|
| customer_id | 顧客 |
| status | 未接触→アプローチ→面談→提案→見積→受注／失注／保留（この8種類で確定） |
| probability | 確度：90／70／50／30／10％の5段階（受注見込み金額＝想定金額×確度） |
| plan_id | 想定プラン（マスタ：月1企画¥70,000／月3企画¥150,000／月5企画¥200,000） |
| monthly_amount | 月額（税別）。プラン選択で自動入力、値引き時は手修正可 |
| contract_months | 契約月数（初期値3） |
| expected_total | 想定金額＝月額×契約月数（自動計算） |
| desired_start_month | 開始希望月 |
| next_action / next_action_due | 次回アクションと期限（**どちらも必須**。受注・失注のときのみ不要） |
| owner_id | 営業担当 |
| lost_reason / hold_reason | 失注理由・保留理由（該当時に必須） |
| won_at / lost_at | 受注日・失注日（月別受注金額の集計に使う） |

### deal_status_logs（ステータス変更履歴）
誰がいつ何から何へ変えたかを自動記録。受注率や滞留日数を後で正しく出すために最初から持つ。

### activities（活動記録）
| 列 | 内容 |
|---|---|
| deal_id / customer_id | 紐づく案件・顧客 |
| type | 面談／電話／訪問／オンライン／メール／その他 |
| occurred_at | 実施日時 |
| user_id | 記録者 |
| summary | 概要 |
| hearing_channels | 現在の集客経路と費用 |
| hearing_sns | SNSの現状 |
| hearing_strengths | 在庫と強み |
| hearing_decision | 意思決定者と検討スケジュール |
| hearing_budget | 予算感 |
| reaction | 反応と反論 |
| next_promise | 次の約束 |

活動を保存する画面で「次回アクション・期限」も同時に更新できるようにする（入力の手間を1回にまとめるため）。

### マスタ
industries（業種）、areas（エリア）、plans（プラン：名称・月の企画数・月額）、lost_reasons（失注理由）。

## 3. 画面遷移（MVP）

```
ログイン
  └─ 案件ボード（MVPのトップ）
       ├─ 案件詳細 ── 活動を記録 ／ ステータス・確度・次回アクション編集
       │     └─ 顧客詳細へ
       └─ 新規案件
  └─ 顧客一覧（検索・絞り込み：担当／優先度／業種／エリア）
       ├─ 顧客詳細（基本情報＋案件一覧＋活動タイムライン）
       ├─ 新規顧客（重複チェック付き）
       └─ CSV取り込み（プレビュー → 重複確認 → 取り込み）
  └─ マスタ管理（部長・充のみ）
```

- スマホ：画面下部に「案件／顧客／記録する／メニュー」のタブ。案件ボードは横スワイプでステータス列を切替。
- PC：左サイドメニュー、案件ボードは全列を横並び表示。
- ダッシュボード・リマインド・制作進捗は後続で追加（MVP完了後のトップはダッシュボードに差し替え）。

### 権限（役割ごとの範囲）
| 役割 | 顧客・案件・活動の閲覧 | 編集 | マスタ・ユーザー管理 |
|---|---|---|---|
| 部長 | 全件 | 全件（削除含む） | 可 |
| 充（運用管理者） | 全件 | 全件（削除含む） | 可 |
| 営業 | 全件 | **自分が担当の顧客・案件のみ**（活動記録は自分の記録のみ） | 不可 |
| 制作 | 受注案件とその顧客のみ | 不可（制作進捗は第2段階で編集可にする） | 不可 |
